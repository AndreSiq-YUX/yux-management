# YUX Mission Safety Foundation Implementation Plan

**Status (2026-08-22):** implementado e verificado na branch `codex/company-intelligence-active-prospecting`. Evidência: backend 387/387, Harness 90/90, contrato Python→JSON Schema→TypeScript sem drift e golden corpus 15/15 aprovado (score mínimo 91, custo mediano 1,9 BRL, p95 1000 ms). Rollback: `docs/runbooks/yux-mission-safety-foundation-rollback.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the cross-runtime, provider-effect, concurrency, cost, privacy and regression controls required before implementing the general Mission Supervisor.

**Architecture:** Pydantic owns Mission wire contracts and exports deterministic JSON Schema consumed by TypeScript. The Action Engine pins immutable capability manifests, classifies recovery, reserves external effects before dispatch, fences concurrent resource claims and issues short-lived mutation leases. Planning budgets, attribution policy, PII-redacted observability and golden missions make model changes measurable and reversible.

**Tech Stack:** TypeScript 5.6, Zod 4, Ajv, PostgreSQL, BullMQ/Redis, Python 3.13, Pydantic 2, FastAPI, Vitest, Pytest and GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-22-yux-autonomous-mission-supervisor-design.md`

## Global Constraints

- This release is a prerequisite for Release 1A; it enables no new customer mutation capability.
- Pydantic is the source of truth only for Harness↔Action Engine wire contracts; TypeScript remains the source for executable domain capability schemas.
- A provider timeout after dispatch is `unknown`, never `failed`.
- Compensatable, pausable and irreversible effects have different mandatory recovery contracts.
- Approved plans execute exact pack and capability versions plus definition hashes; `latest` is forbidden.
- Every resource claim and external mutation carries a fencing token; stale workers cannot mutate.
- Planning stops when its model-call, token, latency or BRL cycle budget is exhausted.
- No ROI metric is known without a versioned pack attribution policy.
- Secrets are dropped from telemetry; PII is tokenized before telemetry export.
- Every model, prompt, retrieval, pack or planner promotion passes the golden-mission gate.
